# Архитектура

## 1. Контекст (C4, уровень 1)

```
 Клиент / менеджер по продажам ──► Личный кабинет (СУОП) ──► Turbo Cloud Calculator ──► Прайс-лист (JSON)
 Аналитик ──────────────────────► CLI turbo-calc ──────────┘
```

Калькулятор — автономный сервис. Он не обращается к биллингу и к базам данных. Единственная зависимость — файл прайс-листа.

## 2. Контейнеры (C4, уровень 2)

| Контейнер | Технология | Назначение |
| --- | --- | --- |
| REST API | FastAPI + uvicorn | Принимает конфигурацию, возвращает смету |
| CLI | argparse | Расчёт из файла, вывод text/JSON/CSV |
| Библиотека `turbo_calc` | Python 3.11, pydantic v2 | Модели, прайс-лист, расчёт |
| Прайс-лист | JSON в пакете | 82 позиции с SKU, ценой, единицей, периодом |

## 3. Компоненты (C4, уровень 3)

| Модуль | Ответственность | Зависимости |
| --- | --- | --- |
| `models.py` | Описывает вход (`Configuration`) и выход (`Estimate`). Проверяет диапазоны и взаимные ограничения полей | pydantic |
| `pricelist.py` | Загружает прайс-лист. Проверяет уникальность SKU и корректность цен. Отдаёт позицию по SKU | stdlib |
| `calculator.py` | Преобразует конфигурацию в разделы сметы. Считает скидку, НДС, итоги | models, pricelist |
| `api.py` | Публикует расчёт по HTTP. Добавляет `X-Request-ID` и журнал | calculator, FastAPI |
| `cli.py` | Разбирает аргументы. Форматирует смету для терминала и файлов | calculator |

Поток данных: `JSON → Configuration → Calculator.estimate() → Estimate → text | JSON | CSV`.

## 4. Ключевые решения

| Решение | Обоснование |
| --- | --- |
| `Decimal` вместо `float` | Деньги требуют точного десятичного представления. `float` даёт ошибки округления |
| Округление каждой строки, итог — сумма строк | Так работает биллинг. Клиент сверяет смету построчно |
| Прайс-лист — данные, не код | Цены меняются чаще кода. Обновление цен не требует релиза |
| Модели `extra="forbid"` | Опечатка в имени поля даёт ошибку, а не молчаливый ноль в смете |
| `Calculator` принимает прайс-лист в конструкторе | Тесты и клиенты с индивидуальными тарифами подставляют свой прайс-лист |
| Один процесс без состояния | Сервис масштабируется горизонтально. Нет базы данных — нет миграций |

## 5. Обработка ошибок

| Ситуация | Поведение |
| --- | --- |
| Неизвестное поле или значение вне диапазона | `422`, список полей с описанием (API); код `2` и `stderr` (CLI) |
| Логическое противоречие (например, резервные копии для Kafka) | `ValueError` → `422` с текстом ошибки |
| SKU отсутствует в прайс-листе | `UnknownSkuError`; `404` для `GET /v1/pricelist/{sku}` |
| Прайс-лист повреждён | Ошибка при старте процесса; сервис не запускается |

## 6. Развёртывание

- Docker-образ на базе `python:3.12-slim`, запуск от пользователя `app`, `HEALTHCHECK` на `/health`.
- За обратным прокси (Envoy, nginx) сервис работает без изменений: он не хранит сессии.
- Горизонтальное масштабирование — несколько реплик за балансировщиком.

## 7. Безопасность

- Нет аутентификации в самом сервисе. Доступ ограничивает шлюз (API-ключ или SSO Keycloak).
- Ограничения размеров списков и значений защищают от чрезмерных запросов.
- Сервис не хранит и не передаёт персональные данные.
